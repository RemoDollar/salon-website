## 🏗️ SCSS Architecture

This project uses a modular **SASS partials architecture** for maintainability and scalability:

| Folder | Purpose |
|---|---|
| `base/` | Global reset and typography styles |
| `layout/` | Header, footer, grid and structural layout |
| `components/` | Individual UI components — buttons, gallery, navigation |
| `style.scss` | Main entry file importing all partials in order |

This architecture allows each section of the UI to be maintained independently, making the codebase clean, readable, and easy to scale.

---

## 💡 Technical Decisions & Problem Solving

**Why SCSS partials over a single stylesheet?**
As the project grew in complexity, a single CSS file became difficult to manage. Implementing a SCSS partials architecture allowed for clean separation of concerns — each component and layout section has its own scoped file, making debugging and updates significantly faster.

**Why Vanilla JavaScript over a framework?**
For a business website of this scope, a full framework like React would introduce unnecessary complexity. Vanilla JS was the right tool — lightweight, fast, and sufficient for the DOM interactions required (navigation toggle, scroll behaviour, interactive elements).

**Mobile-first approach:**
All styles were written mobile-first and scaled up using SCSS breakpoints. This ensures the site performs well on the devices most visitors use — smartphones.
